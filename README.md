# Беседа — свой Discord на Python

Сервер на Ubuntu, клиент для Windows. Текстовые каналы, файлы и картинки, голосовые каналы с Opus.
Рассчитано на компанию до 20–30 человек.

```
server/   — Ubuntu: Starlette + uvicorn, SQLite, UDP-ретранслятор голоса
client/   — Windows: PySide6, sounddevice, Opus
```

## Что умеет

**Текст:** серверы (как в Discord) с приглашениями по коду, текстовые каналы, история с подгрузкой при прокрутке,
правка и удаление, «печатает…», `**жирный**`, `*курсив*`, `` `код` ``, ссылки, @упоминания с уведомлением в трее,
непрочитанные каналы.

**Файлы:** до 50 МБ (меняется в настройках сервера), картинки показываются прямо в чате, вставка скриншота по Ctrl+V,
перетаскивание файлов в окно.

**Голос:** Opus 48 кГц с FEC (восстановление потерянных пакетов), шифрование ChaCha20-Poly1305,
джиттер-буфер ~60 мс. Активация голосом с настраиваемым порогом и индикатором уровня, открытый микрофон или
рация (Push-to-Talk на любую клавишу или боковую кнопку мыши, работает даже когда окно свёрнуто),
усиление микрофона, выбор устройств, громкость каждого собеседника отдельно (0–200 %), заглушить человека
только для себя, самопрослушивание для проверки, выбор битрейта до 96 кбит/с. Индикатор «говорит», звуки входа
и выхода. После обрыва связи клиент сам переподключается и возвращается в голосовой канал.

**Управление:** владелец сервера создаёт, переименовывает и удаляет каналы, выгоняет участников, меняет код
приглашения. Первый зарегистрированный на машине пользователь — администратор.

## Как это устроено

```
Клиент ──HTTPS──▶ nginx :443 ──▶ uvicorn 127.0.0.1:8765   вход, файлы
       ──WSS────▶ nginx :443 ──▶ uvicorn /ws              сообщения, события, управление голосом
       ──UDP────────────────────▶ :50000                  голос (зашифрован, ключ выдаётся по WSS)
```

Сервер звук не микширует: он пересылает пакеты говорящего остальным участникам канала, а смешивает их клиент.
Поэтому нагрузка на сервер маленькая, задержка минимальная.

## 0. Быстрый тест на Windows (без Ubuntu)

Сервер на чистом Python, поэтому для проверки его можно запустить прямо на Windows.

1. `server\start_server_windows.bat`. Первый запуск ставит библиотеки (минуту-две), потом печатает адреса:
   `http://127.0.0.1:8765` — для этого же компьютера, `http://192.168.x.x:8765` — для других в сети.
   Если Windows спросит про доступ Python к сети — разрешите для частных сетей.
2. `client\setup_and_run.bat` → адрес `http://127.0.0.1:8765` → «Создать новый аккаунт» (код не нужен).
3. Второй участник на этом же компьютере: `client\second_client.bat` — отдельный профиль, свой аккаунт.
   В первом окне создайте сервер, в меню ⋮ скопируйте код приглашения, во втором войдите по нему.
   Для голоса на одном компьютере обязательно наушники, иначе будет заводка.
4. С другого компьютера в той же сети — адрес `http://192.168.x.x:8765`. Если не подключается,
   запустите `server\open_firewall_windows.bat` от имени администратора.

Если что-то падает: `client\run_debug.bat` запускает клиент с консолью, а журнал всегда пишется в
`%LOCALAPPDATA%\Beseda\beseda.log`. Данные тестового сервера лежат в `server\data` — удалите папку,
чтобы начать с чистого листа.

## 1. Сервер в Docker (Debian 13 и любой Linux с Docker) — рекомендуется

Нужны: Docker с плагином compose (`docker compose version` должно отвечать), белый IP, лучше домен.
Сервер ставится двумя контейнерами: `beseda` (сам сервер) и `beseda-caddy`, который сам получает и
продлевает HTTPS-сертификат Let's Encrypt.

**Шаг 1. Домен.** Создайте A-запись домена на IP сервера (бесплатно — на duckdns.org). Без домена тоже
работает, но без шифрования.

**Шаг 2. Скопировать папку `server` на сервер** — с Windows в PowerShell (ssh и scp там уже есть):
```powershell
scp -r .\server root@IP_СЕРВЕРА:/opt/beseda
```
(если входите не под root — `scp -r .\server user@IP:~/beseda` и дальше команды через `sudo`).

**Шаг 3. Установить:**
```powershell
ssh root@IP_СЕРВЕРА
```
```bash
cd /opt/beseda
bash deploy/docker-install.sh chat.example.ru     # с доменом → HTTPS
# или
bash deploy/docker-install.sh                     # без домена, по IP
```
Скрипт создаст файл настроек `.env`, соберёт образ, запустит контейнеры, дождётся, пока сервер ответит,
и покажет **адрес**, **адрес админки** и **код регистрации**.

**Порты.** Нужны 80/tcp и 443/tcp (сайт и сертификат) и **50000/udp** (голос). Docker открывает их сам,
но если у хостинга есть брандмауэр в панели управления — откройте их там. Без UDP чат работает, а голос нет.

**Если 80/443 уже заняты** (на сервере уже есть сайты, Nginx Proxy Manager, Traefik…), скрипт это заметит:
Caddy не запустит, а сервер будет слушать `127.0.0.1:8765`. Направьте на него свой прокси, например в nginx:
```nginx
location / {
    proxy_pass http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 3600s;
    client_max_body_size 60m;
}
```

**Управление** — утилита `bctl` в той же папке:
```bash
./bctl status              # состояние контейнеров
./bctl logs                # логи сервера (Ctrl+C — выйти); ./bctl logs caddy — логи HTTPS
./bctl restart | stop | start
./bctl update              # после заливки новой версии папки server: пересобрать и перезапустить
./bctl backup              # архив базы и файлов в ./backups (можно на работающем сервере)
./bctl users               # список пользователей
./bctl reset-password ЛОГИН   # если забыли пароль администратора
./bctl make-admin ЛОГИН | unban ЛОГИН
```
Настройки — в файле `.env` (домен, код регистрации, UDP-порт, размер файлов), после правки `./bctl start`.
Данные хранятся в Docker-томе `beseda_beseda-data` и не пропадают при обновлении и пересоздании контейнеров.
Забрать бэкап на Windows: `scp root@IP:/opt/beseda/backups/*.tar.gz .`

## 1б. Сервер без Docker (Ubuntu 22.04 / 24.04)

Нужен VPS с белым IP. Лучше с доменом — тогда будет HTTPS. Бесплатный домен можно взять на duckdns.org
и направить на IP сервера.

```bash
# скопируйте папку server на сервер, например:
scp -r server root@ВАШ_IP:/root/beseda-server
ssh root@ВАШ_IP
cd /root/beseda-server

sudo bash deploy/install.sh chat.example.ru you@mail.ru   # с доменом и HTTPS
# или
sudo bash deploy/install.sh                               # просто по IP, без шифрования
```

Скрипт поставит всё нужное, создаст службу `beseda`, настроит nginx, брандмауэр (ufw) и сертификат
Let's Encrypt. В конце он покажет **адрес** и **код регистрации** — их нужно раздать друзьям.

Если у хостинга есть свой брандмауэр в панели управления, откройте там 80/tcp, 443/tcp и **50000/udp**.
Без UDP-порта чат работает, а голос — нет (клиент покажет «Нет UDP-связи»).

Полезное:
- логи: `journalctl -u beseda -f`
- настройки: `/etc/beseda.env`, после правки `sudo systemctl restart beseda`
- данные (база + файлы): `/var/lib/beseda` — это и нужно бэкапить
- обновление: залить новую папку `server` и снова запустить `install.sh` — база и настройки сохраняются

Запуск вручную для проверки (без nginx):
```bash
cd server && pip install -r requirements.txt
BESEDA_HOST=0.0.0.0 BESEDA_DATA=./data python3 -m beseda_server
```
Тогда в клиенте адрес `http://IP:8765`.

## 2. Клиент (Windows 10/11)

Нужен Python 3.10 или новее с python.org (галочка «Add Python to PATH»).

1. Скопируйте папку `client` на компьютер.
2. Запустите `setup_and_run.bat`. Первый раз он создаст окружение, поставит библиотеки и скачает
   `libopus-0.x64.dll`. Дальше этот же файл просто запускает программу.
3. Введите адрес сервера (например `https://chat.example.ru`), отметьте «Создать новый аккаунт»,
   укажите код регистрации.
4. Кнопка «+» слева → «Создать сервер». В меню сервера (⋮) — «Пригласить людей»: код приглашения
   отправьте друзьям, они входят через «+» → «Войти по приглашению».

**Готовый .exe для друзей:** после первого запуска выполните `build_exe.bat` — получится папка
`dist\Beseda` с `Beseda.exe`. Её можно заархивировать и раздать: Python у друзей не нужен.

### Звук

⚙ → «Голос и звук»: выберите микрофон и выход, отрегулируйте усиление так, чтобы индикатор в речи доходил
примерно до −20…−10 dB и не краснел, порог активации поставьте чуть выше уровня фонового шума.
Галочка «Слышать себя» — быстрая проверка. Если устройство не открывается, попробуйте тот же микрофон с другим
API (MME / WASAPI / DirectSound — они перечислены в списке). Эхоподавления нет — пользуйтесь наушниками.

## 3. Веб-админка

Откройте в браузере адрес сервера с `/admin` на конце: `https://chat.example.ru/admin`
(на тестовом Windows-сервере — `http://127.0.0.1:8765/admin`). Вход — логином и паролем администратора.
Администратором автоматически становится первый зарегистрированный пользователь, остальных можно назначить в админке.

- **Обзор** — кто в сети и в голосе, число пользователей, серверов, сообщений, место на диске, график
  сообщений за 2 недели, объявление всем, кто сейчас подключён (всплывает у них окном).
- **Пользователи** — поиск, создание, переименование, сброс пароля, «завершить все сеансы»,
  выдача и снятие прав администратора, блокировка (человека сразу выкидывает из чата и голоса, войти он не сможет).
- **Серверы** — переименование, новый код приглашения, передача владения, удаление; каналы
  (переименовать / удалить) и участники (выгнать).
- **Голос** — кто сейчас в голосовых каналах, его UDP-адрес и счётчики пакетов (видно, у кого не проходит UDP),
  отключение от голоса.
- **Сообщения** — поиск по тексту, серверу и автору, удаление.
- **Файлы** — самые большие файлы, удаление, очистка неотправленных.
- **Настройки** — открыть / закрыть регистрацию, сменить код регистрации без перезапуска сервера.
- **Журнал** — последние события сервера; действия администраторов выделены, есть фильтр «только админы».

Забыли пароль администратора — сбросьте его в консоли сервера:
```bash
# Windows (в папке server):
.venv\Scripts\python -m beseda_server.manage reset-password ЛОГИН
# Ubuntu:
sudo -u beseda bash -c 'set -a; . /etc/beseda.env; /opt/beseda/venv/bin/python -m beseda_server.manage reset-password ЛОГИН'
```
Там же есть `users`, `make-admin ЛОГИН` и `unban ЛОГИН`. На Windows перед командой задайте `set BESEDA_DATA=data`,
чтобы утилита нашла базу тестового сервера.

## Ограничения первой версии

- Нет демонстрации экрана и видео.
- Нет личных сообщений (только каналы на серверах).
- Нет ролей кроме «владелец / участник».
- Нет шумоподавления и эхоподавления.

## Протокол (если захочется дописать)

WebSocket `/ws`: первым сообщением `{"type":"auth","token":"…"}`, в ответ `ready` со всем состоянием.
Операции клиента — методы `op_*` в `server/beseda_server/app.py`, события сервера — `ev_*` в
`client/beseda/ui/main_window.py`. Формат голосовых пакетов описан в начале `server/beseda_server/voice.py`.
